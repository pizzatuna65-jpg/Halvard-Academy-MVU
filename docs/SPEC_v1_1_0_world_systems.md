## 0. Shared principles

- **Deterministic, replay-safe.** Every roll is `hash32(seed, dayNo, block, tag)` via the existing `rand01` / `hash32` in `engine.template.js` (the same seed as happenings, `$eng.seed`). Never `Math.random`. A swipe or replay sees the same weather, forecast and rolls.
- **The engine computes; the model narrates.** The model never rolls or does the maths. It reads engine output (`_` fields, `<now>`, `_Log`) and writes only story facts through `<UpdateVariable>`.
- **Established decisions that constrain this work** (HANDOFF §4):
  - D11: technique costs are fixed. **Weather never changes technique costs.** Weather attunement for magic was proposed and **rejected [owner]**.
  - D10: never quietly nerf the player's power.
  - D13: HP is injury. Weather never removes HP by itself; frostbite or heatstroke only if the story writes a named injury.
  - D3/D6: the UI never moves the story; settings go through `commitSetting()` (hidden user message + MVU patch).
  - D14: name gating. UI text about NPCs uses `nameOf()` / `{npc:id}` tokens.
  - D16: modules appear only when relevant (`$ui.unlocks`).
  - Card is the only tracker; the preset's Chekhov / World Sim / Agenda / Time and Place stay OFF.
- **Player control [owner]:** new setting **Weather effects: Off / Flavor / Full**, default **Full** [owner]. Stored in `$ui.wxfx`, set from Student file → Settings with `commitSetting()`, exactly like `$ui.happenings`. It is one row of the Features settings panel (§9).
  - Full: weather + temperature + all effects in §4.5.
  - Flavor: weather and temperature are shown; no effects (no conditions, no bond/recovery/presence/Dove modifiers).
  - Off: nothing is computed; `World._Weather` = ''.
- **Units [owner]:** metric everywhere. The card outputs °C. Prose units belong to the preset: add to the Bridge prompt in `presets/edit_preset.py` one line: `Use metric units in prose (°C, metres, kilometres, kilograms, litres).` Keep the preset's "⏰ Time and Place" prompt OFF (it would invent its own weather in °C/°F and contradict the engine).

## 1. Class-aware presence (time of day)

**Problem.** `<now>` (custom entry 505, generated by `tools/gen_mvu_entries.py`) lists a place's regulars from habits only. On Monday 09:00 at the Main Library it says Etnie, Gareth, Irene are "likely around", but lore uid 131 (Timetable) says all three years follow the same period slots, so every student is in class.

**Data (generate, do not hand-write):**
- `tools/curate_data.py`: parse the Staff line of the NPC Roster (uid 97, source lorebook) into `npcs[id].teaches = [[subject, year]]`. Formats seen: `Combat Y1`, `Magic Theory Y2`, `Etiquette Y3`. Milena teaches "Dark Magic Defense teacher for every year" → `[["Dark Magic Defense", 0]]` (0 = every year). Unknown posts stay unknown (the roster says some are unknown; never invent a teacher).
- Class venues come from the engine `TIMETABLE` strings (single source; `gen_ui.py` already extracts them). Rule: a venue in parentheses wins (Combat Grounds, Potion Halls, Menagerie or Forest, "Doves; Combat Grounds or warded seminar room", club venues). Otherwise Lecture Halls. Saturday P2 "Study Hall" → Main Library. Saturday P3 "Clubs" → each club's venues (`DATA.clubs`).
- Inject into 505 (via `gen_mvu_entries.py`): a compact student map `{id: [lorebookYear, arrives, dorm]}` for Halvard students (group `Year N`), the teacher map, and the timetable with venues.

**Rules in `<now>` (EJS, 505).** Only when `_Period` starts with `P1`/`P2`/`P3` (a real class period, not suspended):
- Student regulars are removed from "Likely around <place>"; add `Students are in class until HH:MM.` Staff regulars stay, except a teacher whose subject is being taught now (they are at the class venue).
- Saturday P2 (Study Hall): at the Main Library, "most students are here (Study Hall)"; elsewhere no students.
- Saturday P3 (Clubs): students are at their club's venue; at a club venue, list that club's members who are at Halvard.
- If {{user}} is at the venue of their own class, add one line:
  `Your class now: <subject> [M|D] (Year <Y>, all dorms|<Dorm> only) at <venue> — teacher <name or "not on record">; classmates on record: <up to 8 ids>`.
  - Y = `Player.Profile.Year`. Classmates = Halvard students with current school year = Y (use the cohort formula: lorebook year + campaign Year − arrives), not in `Campus_State.Graduated`, arrived, and for [D] classes in {{user}}'s dorm. Unsorted {{user}} (before the Entrance Event): "dorm not yet sorted".
  - Teacher: the NPC whose `teaches` has this subject and year Y (or year 0).
- Curfew, lockdown, graduation, incoming-cohort and NPC_status rules from v1.0.3 still apply on top.
- **UI:** the Map card's Regulars list shows `(in class until HH:MM)` after student names during class periods. Compute it in the UI from `CAL.TIMETABLE` and `World`; do not add state.

**Tokens:** about +40 during class periods only.

## 2. Story hooks (a light Chekhov's gun, owned by the card)

Narrator-side debts: an NPC's promise with a time ("Irene: back at noon"), a planted detail meant to pay off, a threat, a secret about to surface. Not {{user}}'s obligations (those are `Commitments`) and not {{user}}'s discoveries (`Clues`).

**Schema (`schema.js`):**
```
Hooks: Rec(v => ({ Note: s(v.Note), Who: s(v.Who), Kind: one of promise|detail|threat|secret (default 'detail'),
  Weight: Int 1-3 (default 1), Due: s(v.Due), Planted: s(v.Planted), _State: s(v._State),
  $abs: n(v.$abs, -1, 1e9, -1), $born: n(v.$born, -1, 1e9, -1) }), 'Note')
```
**Engine (new §8f):**
- New key → `Planted = dstamp`, `$born = absA`.
- `Due` parsed once and anchored exactly like Commitments (`$abs`, reuse `parseWhen`; re-parse only when the Due text changes).
- `_State`: `waiting` | `due` (from 30 min before `$abs` to 3 h after) | `overdue` (later than that) | `old` (no Due, Weight ≥ 2, age ≥ 14 days). Log once when a hook turns `due`.
- `Who` names → NPC ids through the alias map (like `Projects.With`).
- Cap 15; when over, drop Weight-1 hooks first, oldest first (`capRecord` with `dropFirst`).
**`<now>` (505):** `Hooks due now: <title> (<Who>: <Note>)`; `Old hooks (pay off or drop): <titles>` (Weight ≥ 2 only).
**502 rule (`[mvu_update]`):** add a hook when an NPC promises something at a time, or when you plant a detail that should matter later (Weight 1 small, 2 notable, 3 major); remove it once paid off, broken or dropped. At most one new hook per reply.
**504 rule (`[mvu_plot]`):** hooks are debts the story owes; never announce them; pay them off through the world (an NPC returns, a message arrives, a detail resurfaces). NPCs may break promises; that is a beat too.
**UI:** none (narrator notes; hidden from the player's panels [owner]).
**Tokens:** about 20 per hook, at most about 300.

## 3. Gossip that spreads

`Campus_State.Rumours` stays a list of strings (saves keep working). The engine keeps hidden metadata.

- `$eng.rum = { "<rumour text>": { born: dayNo, fate: 'fizzle'|'normal'|'fast' } }`, created when a new string appears.
- Fate roll d20 = `hash32(seed, text, 'rum') % 20 + 1`: 1–3 fizzle, 4–17 normal, 18–20 fast.
- Reach by age (days): day 0 "only witnesses"; days 1–2 "the source's dorm and club"; days 3–6 "most of campus"; days 7–20 "old news, everyone knows". Fast: campus-wide from day 1. Fizzle: dies on day 3.
- Removal: fizzle on day 3, others on day 21 → the engine removes the string from `Rumours` and pushes it to `$ui.rumours_old` (StrList 50, UI only). If the AI removes a rumour, drop its metadata.
- `<now>`: up to 5 newest: `Rumours going around: "<text>" (<reach>, day <n>)`.
- **UI:** Notebook → Journal shows a reach tag next to each rumour, and old rumours faded.
- **Tokens:** about +10 per live rumour.

## 4. Seasons, weather and temperature

### 4.1 Seasons [owner: real-life months, northern hemisphere]
M12, M1, M2 Winter · M3–M5 Spring · M6–M8 Summer · M9–M11 Autumn. Checked against canon: Harvest Festival (M10) autumn, Sports Day (M6) summer, Month 12 holiday in winter. The Academy Trip (M11, Sunreach Bay) is abroad: while `_Curfew` starts with "Away from campus", `World._Weather` says `Away: local weather is the narrator's call` and no weather effects apply.

### 4.2 Sky, rolled per block
Blocks: **morning 06:00–11:59, afternoon 12:00–17:59, night 18:00–05:59** (night belongs to the day it starts on).
States: Clear, Cloudy, Overcast, Fog, Rain, Storm. Weighted pick with d100 over (base × block × transition).

Base weights:

| Season | Clear | Cloudy | Overcast | Fog | Rain | Storm |
|---|---|---|---|---|---|---|
| Winter | 25 | 20 | 25 | 10 | 18 | 2 |
| Spring | 30 | 25 | 15 | 8 | 20 | 2 |
| Summer | 50 | 22 | 8 | 3 | 12 | 5 |
| Autumn | 28 | 22 | 20 | 12 | 16 | 2 |

Block multipliers: morning Fog ×2, Storm ×0.5 · afternoon Fog ×0.3, Storm ×1.8 · night none.

Transition multipliers from the previous block (morning uses the previous night, so weather is continuous across days):

| Previous | Multipliers for the next block |
|---|---|
| Clear | Clear ×2, Cloudy ×1.2, Overcast ×0.6, Rain ×0.4, Storm ×0.6 |
| Cloudy | Cloudy ×1.4, Overcast ×1.3 |
| Overcast | Overcast ×1.5, Rain ×2, Clear ×0.5 |
| Fog | Clear ×1.5, Cloudy ×1.3, Fog ×0.4 |
| Rain | Rain ×1.8, Overcast ×1.5, Storm ×1.3, Clear ×0.4 |
| Storm | Rain ×2, Overcast ×1.5, Storm ×0.5 |

Chain without state: to get today's blocks, start 3 days earlier with no transition and roll forward (9 blocks of warm-up + today's). Pure function of (seed, day). A Python simulation of these weights (20,000 days) gave: afternoon rain after an overcast morning 33–41% (base about 20%); afternoon clear after a clear morning 48–70%; summer about 56% clear.

Sub-rolls:
- Rain intensity d100: 1–45 light, 46–85 steady, 86–100 heavy; +15 if the previous block was Rain/Storm.
- Snow: in Winter, Rain becomes Snow with 60% (M12) / 70% (M1–M2); +15 at night and morning; never when the block temperature is above 3 °C.

### 4.3 Wind (separate roll per block)
d100 ≥ threshold → Windy; 100 → Gale. Threshold starts at 93 (≈8%). Lower it (more wind) by: afternoon 5, Spring/Autumn 4, Rain/Snow 6, previous block windy 15. Raise by 3 when Clear. Storm is always at least Windy; Storm + d100 ≥ 95 → Gale. Windy combines with any sky ("clear, windy", "rain, windy").

### 4.4 Rare weather (target 1–3 blocks a month)
| Event | Condition |
|---|---|
| Lightning storm | Storm in Spring/Summer, afternoon or night, d100 ≥ 71 |
| Hail | Storm in Spring/Summer afternoon, d100 51–70 |
| Blizzard | Snow + Windy/Gale in Winter |
| Dense fog | Fog in Autumn/Winter morning, d100 ≥ 80 (visibility a few metres) |
| Heatwave | Summer, one daily roll d100 ≥ 98: the whole day Clear, +8 °C |

A rare event adds a toast and a `_Log` line when it begins.

### 4.5 Temperature (°C) [owner: table approved]
Monthly mean: M1 2 · M2 3 · M3 7 · M4 11 · M5 15 · M6 19 · M7 21 · M8 21 · M9 17 · M10 12 · M11 7 · M12 3.
Block: morning −2, afternoon +4, night −4. Weather: Rain/Snow −2, Summer Clear afternoon +2, Heatwave +8, Blizzard −6. Daily variation: one roll per day, −3..+3.
Labels: ≤0 freezing · 1–7 cold · 8–14 cool · 15–21 mild · 22–27 warm · ≥28 hot.

### 4.6 Output
- `World._Season` (e.g. `Autumn`), `World._Weather` (e.g. `Afternoon, autumn: steady rain, windy, 9 °C (cool)`, about 15 tokens). Engine-written, read-only for the AI.
- `$ui.wx` for the UI: `{ season, blocks: [today's blocks up to now: {sky, rain, snow, wind, rare, temp}], forecast: {...} }`.
- Bracelet: one weather chip (Font Awesome: sun, cloud, cloud-sun, smog, cloud-rain, cloud-showers-heavy, snowflake, bolt, wind) with °C; tooltip = `_Weather`.

### 4.7 Divination Society forecast [owner]
- Posted every day at 07:00 on the **Notice Board** (castle Floor 1 entrance hall) by the **Divination Society** (lore: a club in the Club Rooms; the Observation Tower is theirs for celestial work). Signed by the society, never by a member's name (D14).
- Content: tomorrow's morning / afternoon / night sky + temperature label.
- **Not 100% right [owner, 70–80%]:** per block, d100 = `hash(seed, day+1, block, 'fc')`; ≤ 75 → the true sky; otherwise a neighbouring wrong one (Clear↔Cloudy, Cloudy↔Overcast, Overcast↔Rain, Rain↔Storm, Fog↔Cloudy). Rare events are never forecast.
- Where it shows: Notebook → Notice Board, as an official-style card "Divination Society — tomorrow's skies" with a small disclaimer line ("The Society accepts no responsibility for umbrellas."). The bracelet and Planner do **not** show it; the player has to check the board. The Notice Board module unlocks as now (first notice or entering any castle place).
- `<now>`: `Divination Society forecast on the Notice Board for tomorrow: <summary>` (the narrator knows what students can read).

### 4.8 Real effects (Full mode only)

**Indoors or outdoors.** Outdoor = location category "Sport and Grounds", plus Courtyards and Rooftop (`data/locations.json` categories; generate the list in `gen_engine.py`). Everything else is indoors. Outdoor minutes this update: both before and after locations outdoor → all elapsed minutes; one of them → half; none → 0.

**Gear = Inventory items (§8).** Weather gear is not a separate list: the engine scans the names of `Inventory` items (any Kind, usually `gear`), case-insensitive, for keywords: `umbrella`; `waterproof|oilskin|rain cloak|raincoat` (waterproof); `wool|scarf|winter cloak|mittens` (warm); `sun hat|straw hat` (sun). If the Inventory feature is off (§9), gear counts as absent and the weather effects apply without it.

**Conditions (new record `Player.Conditions`: `{ "<name>": { "Effect": "", "Since": "" } }`).** The engine adds and clears them; the AI may remove one when the story covers it (a Medical Centre visit, a hot bath).

| Condition | Gained when | Effect | Clears |
|---|---|---|---|
| Soaked | outdoor ≥ 20 min in Rain/Snow (heavy: ≥ 5 min). Umbrella prevents it unless Windy/Gale/Storm; waterproof gear always prevents it | rest/sleep stamina recovery ×0.5 | 60 min indoors |
| Chilled | outdoor ≥ 30 min at ≤ 0 °C, or Soaked at ≤ 8 °C. Warm gear: ≤ −5 °C / Soaked ≤ 3 °C | Stamina −10 per outdoor hour | 60 min indoors |
| Overheated | outdoor ≥ 60 min at ≥ 28 °C under Clear/Cloudy. Sun gear: ≥ 31 °C | Stamina −10 per outdoor hour | 30 min indoors |
| Head cold | a daily roll at the first update of a new day: 15% if Soaked or Chilled the day before; +5% during a flu wave; +5% if Stamina < 30% | Stamina capped at 80% of Stamina_max for 2–4 days (rolled) | the days pass, or the Medical Centre (the narrator removes it) |

- **Flu wave (Winter):** 1–2 per winter, 5 days each, seeded. `<now>`: `A cold is going around campus.` plus 1–2 seeded student regulars "off sick in their dorm" (removed from Likely around).
- **Sleep quality:** night Rain (light/steady) = cosy, stamina recovery +10%; Storm / Lightning storm = restless, −20%; night ≥ 22 °C = restless, −10%. Applies to `Resting: sleep` only.
- **Bonds (Persona-style):** the daily progress cap (3) is +1 for a bond whose progress came at an indoor place during Rain/Snow/Storm ("stuck indoors together"), or at an outdoor place under Clear/Cloudy at 15–27 °C. Star Night with a Clear night: +1 as well. At most +1 per bond per day.
- **NPC weather moods (canon only):** `data/weather_moods.json`, hand-written from lore. Today only one canon source: Idris (lore uid 105) "Cold-blooded: sluggish in cold weather, loves sun" → `<now>` line when he is present and it is cold / sunny. Add more only when the lore says so.
- **Presence (Stardew-style schedules):** in Rain/Snow/Storm, regulars of outdoor places are listed as `moved indoors (Gymnasium, Common Rooms)` (lore: the Gymnasium is used heavily in bad weather). Clubs whose venues are all outdoor (Running, Soccer, Walking, Gardening, Fishing) practise indoors or cancel; **exception:** the Fishing Club goes out in rain (best fishing).
- **Happenings:** add `outdoor: true` to outdoor items in `data/happenings.json` (verify each: pickup_match, boat_capsize, club_tables, airship_over, garden_overgrowth, menagerie_loose, dove_sweep, fallen_tree); they are skipped when the day's morning or afternoon is heavy Rain, Storm, Blizzard or Hail. Add weather-only items with a `weather` condition, all lore-grounded, NPC-free, `where` a real location: snow-clearing crew at the Groundskeeper's Lodge (paid, 20–40 points a shift, the canon rate), storm clean-up after a Lightning storm or Gale, Dove patrols doubled in Dense fog. `fallen_tree` weight ×3 on the day after a Storm/Gale.
- **Hidden magic (stealth):** if `Hidden.Dove_attention` rose this update, {{user}} is outdoors, and the block has Fog, heavy Rain, Storm or Blizzard → the engine halves the rise (round up) and logs it. 502 gets one line so the AI knows.
- **Outdoor battles:** when `Battle.Active` and outdoors, `<now>` and the Battle panel add a field line: wet footing (Rain/Snow), low visibility (Fog/Dense fog), gusts (Windy/Gale), heat (≥ 28 °C). 504: the narrator uses it; the engine does not change costs or HP.

## 8. Inventory ("Bag") [owner]

A simple item tracker: "I buy a Star Cookie to eat tonight" → the cookie is in the Bag until it is eaten.

**Schema:** `Inventory: Rec(v => ({ Qty: Int 1–99 (default 1), Kind: CIEnum ['other','food','drink','gear','gift','book','reagent'] (default 'other'), Note: s(v.Note), Plan: s(v.Plan) }), 'Note')`. Key = the item name as bought ("Star Cookie").
- `Plan` is free text only ("tonight", "for Etnie's birthday"). **No reminder in `<now>` and no date parsing [owner].** It is shown in the Bag and the narrator sees it in `<current_state>`.

**Engine (§8h):**
- Merge keys that differ only by case or surrounding spaces (Qty adds up, Note/Plan: keep the newer non-empty).
- Qty ≤ 0 → remove the item. Cap 40 items (drop Kind other/food first, oldest first; never gear).
- **Sunfizz bottles (canon: "2 points back per returned bottle") [owner]:** when the Sunfizz Qty goes down, the engine adds the same number of `Empty Sunfizz bottle` (Kind other). When `Empty Sunfizz bottle` goes down and {{user}} is at the Commissary or The Mall, the engine pays +2 points per bottle, logs `+N returned Sunfizz bottles` in Transactions, and writes a `_Log` line. Elsewhere, a drop is just a drop (no payment).

**502 rule (about 70 tokens):** `Inventory {"<item>": {"Qty": 1, "Kind": "food|drink|gear|gift|book|reagent|other", "Note": "", "Plan": ""}}`: add what {{user}} buys, receives or finds and keeps; lower Qty when it is used, eaten, given away or lost; Plan only when {{user}} states one. Log the purchase in Transactions as before. Return Sunfizz bottles by lowering "Empty Sunfizz bottle"; the engine pays.

**UI:** Student file → new **Bag** tab (unlock `inventory` at the first item). Items grouped by Kind with Qty, Note and Plan. Buttons fill the chat input only (D6): **Use** ("I eat/drink/use the <item>."; the verb follows Kind), **Give…** ("I give the <item> to "), **Drop** ("I leave the <item> behind."). The Shop's Buy button is unchanged (it drafts the purchase; the AI then adds the item).

**Tokens:** about 6–8 per item; about 300 at the cap.

**How turning a feature off works:**
- `$ui.off: StrList` of feature ids that are off (hidden from the AI). Happenings and weather keep their own level fields (`$ui.happenings`, `$ui.wxfx`); level `off` counts as off.
- **Rules:** each toggleable feature's lines in 502 / 504 / 505 are wrapped in an EJS gate, e.g. `<%_ if (!OFF.includes('letters')) { _%> … <%_ } _%>`, with `OFF = getvar('stat_data.$ui.off') || []` at the top of each entry (EJS reads `$` keys through getvar; only `{{format_message_variable}}` omits them). The untagged-entry list (D2) does not change.
- **State is parked, not deleted [owner]:** engine §0b moves the module's state into `$ui.parked.<id>` (hidden) and leaves the module empty, so `<current_state>` no longer carries it; while off it is not processed and does not unlock. If the AI still writes into a parked module, the engine merges that write into the parking instead of dropping it. Turning the feature on restores the parked state (engine catch-up rules still apply once, e.g. an overdue commitment is logged).
- **UI:** tabs, panels, bracelet chips and buttons of a feature that is off are hidden. For features that are on, the D16 unlock rules apply as before.
- **Token numbers:** rule costs are measured at build time by `tools/gen_mvu_entries.py` from each gated block (same heuristic as `tests/token_audit.cjs`) and injected into the UI as `FEATURE_COST`; state costs are computed live in the UI from the current state (YAML-like length / 3.6).
