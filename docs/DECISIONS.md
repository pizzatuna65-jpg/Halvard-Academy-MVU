# Established decisions

Do not break these without the owner's approval; when a change touches one, name it. Read only the section for the area you work
on. When the owner approves a new standing decision, add it here in one or two lines (what holds, and where it lives), not its history.

## 1. Framework and state
- **MVU ZOD schema** (D1): `z.boolean()` (never `z.coerce.boolean()`), clamps via `transform`, defaults via `prefault`, and tolerant coercion.
  - Prefix `_` means AI-visible but engine-written. The engine reverts AI changes to `_Techniques`, `_Affinity` and `_True_magic` unless the Builder authorises them.
  - Prefix `$` means hidden from the AI. Since 1.11.0 entry 501 renders `<current_state>` itself (EJS, `getvar('stat_data')`): it omits `$` keys, empty values and the retired `Bonds.*.Progress` / `_Event_ready`, as YAML. Before that, Tavern Helper's `{{format_message_variable}}` did the `$` omission (verified).
- **Cast Sheet** (1.5.1, owner-approved plan P1, changes "Lore activation → keyword WI" for present NPCs): custom 509 (@D1) is generated by `gen_mvu_entries.py` from `509.template.ejs` plus every NPC's lore text, one EJS section per NPC, so EJS inside lore still renders. The engine picks the sheets (`$ui.cast`: `full` at most 4, `brief`, plus `spoke` / `gone` / `ment` from the reply's prose); `merge_lorebooks.py` wraps every NPC keyword entry so it prints nothing while that NPC has a full sheet. 1.99.6 (bug-hunt audit T5): while they are only mentioned (not in Scene.Present or a brief sheet, and not named in the player's new message, `lastUserMessage`) it prints only the public part of their lore (the info layers' public labels, the first sentence of their Personality, their Now line, no `<narrator_only>`); Features `mention_brief` turns that off. `mention_brief` rebuilds the gate last; `gen_mvu_entries.py` `GATE_RX` reads the full lore after `/* full lore */`. The last-mile gate 510 (@D0) sits before 503, so `<UpdateVariable>` stays last.
- **Every enabled entry is tagged `[mvu_update]` or `[mvu_plot]`** (D2). The only untagged enabled entries are uids 0, 20, 97, 131, 132, 134, 501, 505 and 506 (1.58.0, U9: the update model needs the Price Guide's names for `/Purchases`); the disabled control entries 500 (`[initvar]`) and 507 (`[config_override]`) are untagged by design.
- **Engine is deterministic and replay-safe** (4.6). It is a pure function `runEngine(after, before, text, seedHint, userText)` (1.12.0: `userText` is the player's last visible message, read by the hook from `SillyTavern.chat`). 1.20.0: it runs `ENGINE_STEPS` in order; each `step*(c)` reads the values earlier steps put in `c` and adds what later steps use. Save migrations go in `stepMigrate` (flagged, run once per version change, on S and a copy of B), never inside a step. To prove a refactor changes nothing, run tests with `ENGINE_DIFF=<older engine.js>`.
  - Never use `Math.random`.
  - Happenings are seeded by `$eng.seed`, which is set once from the creation time of the first processed message.
